# 從照片生成到下單：迭代與驗收計畫

日期：2026-09-05。先修正目前生成與預覽流程，再用固定樣本決定模型與生成策略，最後重建可履約的結帳流程。

本文件記錄本輪程式碼變更與後續驗收門檻；「已實作」不等於已部署或已通過真實供應商驗證。本次沒有執行付費生成 benchmark、列印打樣或真實付款。

## 四項需求對照

| 使用者需求 | 本輪交付 | 下一個決策 |
| --- | --- | --- |
| 1. 輔助視角是否同圖生成再裁切，以改善細節一致性 | 保留四格路徑，Pro 明確請求 2K；依實際原生像素裁切，拒絕不合規格的版面；單視圖修正只替換指定視角 | 以相同有效解析度比較「同圖裁切」與「確認基準圖後生成其餘三面」，以一致性、細節與每組通過成本決定 |
| 2. 當前圖片生成模型與成本橫評 | [圖片研究](../research/2026-09-05-image-model-comparison.md)：官方版本、輸入／尺寸能力、價格口徑與四視圖成本 | 先做小樣，篩選出值得擴大實測的模型；不以行銷宣稱選品質冠軍 |
| 3. 當前 3D 生成模型與成本橫評 | [3D 研究](../research/2026-09-05-3d-model-comparison.md)：Meshy、Tripo、Rodin、Hunyuan、HiTem3D／Hi3D 的 API、版本、輸入與費用差異 | 固定照片／四視圖，比較可用幾何、製造性、修模時間與總成本，再決定接入及預設版本 |
| 4. 用戶預覽網頁工具體驗優化 | 固定視角、灰模／貼圖／線框、手機畫面、剖面座標、完整模型載入、材質與資源分工；四視圖可放大對照原照 | 完成桌機與手機操作驗收；用真實模型量測載入與旋轉效能 |

## 階段 1：本輪已實作，交由 PR 驗證

- 圖片模型共用映射：保留歷史設定相容性，Pro 選項解析為 stable `gemini-3-pro-image`，避免選 Pro 卻呼叫 Flash。
- 將使用者編輯的色盤與色數傳入風格基準、多視圖及修正路徑；修正指示傳入指定視角的請求。
- 四格採原生裁切，不把 1K 放大冒充 2K 細節；Pro 四格明確指定 2K 正方形。四格生成是否更一致仍是待驗證假設。
- 單視圖修正加入有到期時間的交易保留機制；成功才計次，失敗保留舊圖與額度，過期回應不能覆寫新結果。
- 預覽保留完整 OBJ／GLB 階層與來源材質，以外層縮放／定位配合剖面；來源與預覽材質分別管理，舊載入回應不能覆蓋新檔。
- 提供立體、正、背、左、右、俯視及灰模／貼圖／線框；STL 使用受光材質，尺寸標示為原始座標單位。
- 預設完整生成預估為視角 3 點＋HiTem3D 6 點＝9 點；在扣點前提示餘額缺口與逐步扣款。更換方案時重新顯示估算。
- 生成失敗的退點、失敗狀態及對應費用歸零採同一筆交易，避免已退款仍算支出；退款交易不可用時保留可對帳狀態。
- 暫時性操作失敗保留可操作的已儲存作品；成功後清除舊錯誤，耗時操作的前端 timeout 配合後端。
- 風格重新分析期間防止重複分析／生成及取消造成的狀態錯配，分析與儲存完成後才恢復操作。

本輪維持現行 3D provider 預設與新帳戶贈送 3 點；贈額只能涵蓋預設視角步驟。加值、付款、列印下單仍未開放，不把 9 點說成實體商品總價。

### 本輪 acceptance checklist

- [x] 已以程式碼查核上述模型映射、色盤傳遞、單視圖修正、預覽與成本提示的實作範圍。
- [x] 兩份研究已區分官方 API 價格、會員／試用額度、成本假設及未實測項目。
- [x] 已新增模型／色盤／裁切／修正交易與預覽場景的自動化測試案例；本文件不代替 PR 的實際測試結果。
- [x] [驗證紀錄](../research/2026-09-05-iteration-validation.md)附上 build、lint、型別、36 項測試與桌機／手機畫面；明列未完成的端到端及付費驗證。
- [ ] 桌機與手機驗證：STL、複合 OBJ、帶貼圖 GLB、無效檔、快速換檔；模型完整、切面正確、縮放可用且無控制項遮住主要操作。
- [ ] 驗證六個固定視角、拖曳／觸控、燈光、模式切換、截圖與全螢幕；尺寸說明不誤稱為毫米或可直接列印。
- [ ] 驗證風格重分析、重複點擊、取消、短暫斷線與重試；未成功的操作不能提前解鎖生成或丟失舊作品。
- [ ] 真實供應商另行驗證 stable 模型可用性、2K 回傳、色盤／hint 遵循及實際扣費；mock 測試不能證明畫質與商業帳務。

## 階段 2：固定樣本品質與成本 benchmark

以兩份研究作規格與價格基準，執行前確認付費額度、樣本使用權、帳戶區域及模型版本。先用每類一件的小樣淘汰不合格方案，再依研究規格擴大；保留現行基準，不一次全面換供應商。

1. 固定有使用權的輸入與真實四面參考，涵蓋不對稱配件、文字、細肢、毛髮、透明／反光等難例。盲評用的背面照片不可混入單圖實驗。
2. 比較 A「同張 2×2 原生裁切」、B「確認基準圖後生成其餘三面」；統一物件占比、色盤、角度定義與每視圖有效像素，不能用放大圖片混充同解析度。
3. 圖片初選依研究比較 Gemini、Seedream、FLUX、GPT Image 的有限設定；單獨計算整組重生與單視圖修正成本。
4. 3D 分別比較原照片直出與同組四視圖輸入；只對官方真正支援多視角的 API 使用多圖，不把拼圖輸入算多視角 API。
5. 保存 provider usage：輸入雜湊、requested／resolved model、API 版本、prompt、尺寸、品質、視角順序、seed、request／task ID、usage、開始／結束時間、錯誤與重試關聯。
6. 供應商成本按原幣與實際帳務核對；產品 credits 另列。記錄失敗／退費、儲存傳輸、後處理、修模與打樣，避免只比較成功一次的列表價。

主指標：`每個通過成果成本＝全部嘗試的生成、修正、後處理、傳輸、人工與打樣成本 ÷ 通過成果數`。同時報告首次通過率、四面一致性、關鍵細節、p50／p95 等待時間與使用者接受率。

### 階段 2 acceptance checklist

- [ ] 測前固定樣本、評分規則、最高重試次數與預算；至少兩位評分者盲評，保留不同意見及全部失敗案例。
- [ ] 兩種視角策略按相同有效解析度比較；角度顛倒、跨格部件與錯誤配件列為失敗，不只看圖片好不好看。
- [ ] 3D 同時看灰模及貼圖，記錄幾何缺陷、顏色分區與指定尺寸切片；不可由 PBR 外觀推定可多色列印。
- [ ] 同一固定裝置記錄預覽首屏、載入 bytes、面數、旋轉效能；若需減面，保留原製造檔與派生預覽檔的關聯。
- [ ] 用實際 usage／帳單校正估算，明列每個通過成果成本及樣本數；不得發布未經實測的品質排名。
- [ ] 切換前約定最低品質、最高可用件成本、p95 與製造門檻；入圍方案小流量驗證且可回退，歷史作品不自動重生。
- [ ] 依官方停用時程安排現行 Flash 版本遷移驗證；版本可用性修復與效果優劣決策分開記錄。

## 階段 3：完成可製造與履約條件後重建結帳

**禁止直接解封 legacy 下單／付款端點。** 新流程應以「確認模型與實體規格 → 伺服器報價 → 核對運送與總價 → 付款 → 生產／出貨追蹤」建構；先讓使用者核對具體商品及金額。

### 結帳重新開放的必要 acceptance checklist

- [ ] 明確來源單位、實體高度／寬深與縮放；在實際材質／設備條件下檢查封閉性、薄壁、孤立零件、底面、顏色及切片結果。
- [ ] 區分生成完成、可預覽、待人工修正、可製造；未通過檢核者不能付款下單，修正後保留結果與原因。
- [ ] 報價鎖定模型版本／檔案雜湊、優化版本、尺寸、材質、色數、數量、收件地區與有效期；任一變更須重新報價。
- [ ] 價格由後端計算，核對商品、運費、稅額、折扣、幣別與最終總額；地址必填欄位及運送範圍由相同規則驗證。
- [ ] 訂單建立與付款具 idempotency；雙擊、重新整理、逾時及重送 webhook 只建立一個訂單／付款，不依前端成功畫面認定已收款。
- [ ] 定義付款失敗、逾期、取消、退款及部分退款狀態；交易記錄可對帳，付款退款與生成點數退還分開處理。
- [ ] 已付款、待排產、生產中、已出貨等狀態有合法轉移及取消界線；退款／重印／客服流程有實際負責者與可追蹤紀錄。
- [ ] 用付款沙盒完成成功、失敗、驗證、重送、逾時、退款全流程；以指定尺寸實物打樣驗證報價與交期假設，再審核上線。

目前僅完成程式碼與公開文件層面的修正／研究。供應商實際品質、接受率、製造成本及結帳可履約性仍待上述階段取得證據。
