# Dream Forge Repository Contract

Photo-to-3D application: Next.js frontend in `app/`, Firebase Functions in `functions/`, and Cloudflare integration code in `workers/`. Use package manifests for current versions rather than duplicating version tables here.

## Invariants

- Keep the frontend statically exported: `app/next.config.ts` uses `output: 'export'`, trailing slashes, and unoptimized images. Firebase Hosting serves `app/out`; do not add request-time Next.js server features without changing the deployment contract.
- UI strings use `next-intl`. Update both `app/src/messages/zh-TW.json` and `app/src/messages/en.json`; locale routing and the default locale come from `app/src/i18n/config.ts` and `navigation.ts`.
- Preserve the distinction between client state (Zustand), server state (React Query), and Firestore subscriptions. Reuse existing provider and handler boundaries under `functions/src/`.
- User, job, transaction, session, pipeline, order, and shipping-address writes go through validated Cloud Functions. Preserve the read ownership and admin-only configuration exceptions in `firestore.rules`; do not replace server validation with UI checks.
- Functions target Node.js 22 (`functions/package.json`). API credentials belong in the existing backend secret configuration, never frontend bundles or committed environment files.
- Showcase assets and `app/src/config/showcase-images.ts` are generated by `app/scripts/optimize-showcase-images.mjs`; modify source images or the generator, then run `npm --prefix app run optimize:showcase`.
- `app/AGENTS.md` contains Next.js-generated guidance. Preserve its managed block; read the relevant installed Next.js guide before framework changes.

## Verification

Run from the repository root after installing the relevant package's dependencies:

- Frontend code: `npm --prefix app run lint`. Run `npm --prefix app run build` for route, rendering, configuration, or production-output changes. Its prebuild step regenerates showcase assets; review the resulting diff.
- Functions code: `npm --prefix functions run build`.
- No `test` script is currently defined in the frontend or Functions package. Record focused behavior checks and any missing coverage; a successful build alone does not validate generation, billing, or access control.
- Documentation or instructions only: `git diff --check`, plus path and contract checks; application builds are unnecessary.

Firebase deployment commands and provider calls can change live services or incur charges; they are not local validation. Use them only within the task's existing authorization. Inspect the relevant script, Firebase target, and credentials route before integration or deployment work.
